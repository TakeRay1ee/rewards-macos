# 运行与恢复

本页说明本地服务的日常操作。安装和账号配置入口见[README](../README.md#快速开始)。

## 常用操作

| 目标                      | 操作                                                      |
| ------------------------- | --------------------------------------------------------- |
| 打开服务与界面            | `bash start.command`；已运行的服务会继续使用当前实例      |
| 执行一轮                  | 界面“运行管理”选择全部或部分账号，确认后启动              |
| 停止当前批次              | 先用“停止”；需要立即终止时使用“强制停止”                  |
| 重启服务、重新读取 `.env` | 界面“运行管理”或 `bash restart.command`                   |
| 诊断端口、依赖和服务      | `bash doctor.command`                                     |
| 关闭监控服务              | `bash stop.command`；是否同时停止 API 由终端提示确认      |
| 重新进行人工登录          | `npm run manual-login -- you@example.com --platform both` |

关闭网页不会停止引擎。停止 API 会失去当前控制连接；正常退出先处理其拥有的运行。不要按进程名批量结束系统中的 Chrome，因为它们可能属于其他工作。

`stop.command` 不会移除每日调度。若需要暂停自动触发，应分别停用每日代理和补跑守卫；只关闭网页或监控服务不等于暂停计划任务。

## 本地服务

| LaunchAgent                | 职责                                                |
| -------------------------- | --------------------------------------------------- |
| `local.rewards.api`        | Control API 常驻服务，默认 3010                     |
| `local.rewards.monitor`    | 监控、界面与受限管理入口，默认 3000                 |
| `local.rewards.daily`      | 每日上海时间 00:00 触发调度器（系统时区需保持上海） |
| `local.rewards.dailyguard` | 每 600 秒检查需要补跑的账号                         |
| `local.rewards.keepawake`  | 交流电下通过 `caffeinate -s` 保持整机唤醒           |

机器睡眠、电源状态、系统权限及登录用户会影响触发时机。LaunchAgent 是用户会话内的部署方式，不是无条件的跨所有系统状态运行保证。

修改每日时间：

```dotenv
REWARDS_DAILY_HOUR=0
REWARDS_DAILY_MINUTE=0
```

然后只重新注册每日代理：

```bash
bash scripts/macos/install-launchd.sh --only local.rewards.daily
```

每日守卫使用固定 `Asia/Shanghai` 自然日；launchd 的日历触发使用 Mac 的系统时区，因此精确上海零点触发需要系统时区为上海。安装器会提示系统时区不一致，运行环境也写入 `TZ=Asia/Shanghai`。重新注册会替换相应 LaunchAgent，不要在有相关管理操作进行时重复执行安装脚本。机器在零点睡眠或退出登录时无法保证当时执行，恢复可用后由补跑守卫处理。

## 并发设置

`REWARDS_CONCURRENCY=3` 表示本轮最多三个 worker；三个账号各分配一个 worker，更多账号均衡分到三个 worker 内。worker 之间按 `accountDelay`（默认 20–40 秒）错峰启动，之后任务并行进行；同一 worker 内的后续账号仍保留间隔。零点开始调度，不要求所有浏览器在同一瞬间启动。

显式并发优先于旧 `REWARDS_FORCE_CLUSTERS`，不会因内存估算静默降到一或二。未设置这两项时，调度器才按可用内存、预留与每账号实测占用推导；没有实测时使用初始估算。常用环境变量：

| 变量                           | 默认       | 含义                                                                  |
| ------------------------------ | ---------- | --------------------------------------------------------------------- |
| `MONITOR_RESERVE_GB`           | `1.5`      | 为系统和界面预留的内存 GiB                                            |
| `MONITOR_DEFAULT_FOOTPRINT_MB` | `700`      | 尚无实测值时的每账号占用估算 MiB                                      |
| `REWARDS_CONCURRENCY`          | 示例为 `3` | 明确 worker 上限/目标数，仍不超过本轮账号数                           |
| `REWARDS_FORCE_CLUSTERS`       | 未设置     | 旧配置；未设置显式并发时，`all` 为每账号一 worker，或填正整数覆盖预算 |
| `API_PORT`                     | `3010`     | Control API 端口                                                      |
| `MONITOR_PORT`                 | `3000`     | 监控与界面端口                                                        |

内存估算不等于实际浏览器峰值。资源不足、浏览器启动失败和外部服务限制都可能使某账号失败，界面应显示实际结果。

只读预演不会执行任务：

```bash
node monitor/server/scheduler.mjs run --accounts 1,3 --dry-run
node monitor/server/dailyGuard.mjs --dry-run
```

需要从终端真正执行指定账号时：

```bash
node monitor/server/scheduler.mjs run --accounts 1,3 --reason manual
```

这条命令会启动外部账号任务。手动选择账号不改变其他账号配置。

## 恢复行为

**活动失败与账号结果。** 活动可以继续执行独立的后续阶段，但终态错误会进入该账号最终结果。成功、跳过、没有观测到积分与失败是不同状态。

**API 异常退出。** API 把运行身份、账号选择、日志和有限历史写入 `.control-api/runtime.sqlite`。重启后仅在 PID、创建时间、进程组和命令摘要匹配时接管存活任务。身份无法确认会拒绝重复启动或盲目停止。

**日志流缺失。** 接管进程无法重新连接原 stdout 管道。界面会提示当前数据是最后观测值，暂停根据陈旧日志判断停滞；保留进程控制不等于恢复完整实时观测。

**监控重启。** 监控先读取持久事件和摘要水位，再接收 API 增量。日志按稳定批次身份分发，迟到的上一轮日志更新对应旧批次，不写入新轮。

**账号停滞。** 看门狗保存本轮所有未完成账号，携带预期批次身份停止原轮，等待其真正结束，再通过幂等请求安排恢复。派发进程不等于已经启动；调度回执失败或不明会明确提示需要处理。

**每日补跑。** 守卫合并 API 持久历史与监控记录，按账号成功终态选择未完成项。旧版记录如果只有“已启动”而没有稳定身份和完整终态，会要求确认，避免自动重跑无法判定的历史任务。

**旧数据。** 升级不会凭空补回缺失事实，也不会自动改写全部旧积分。金额未知继续为空；某一批次成功不表示全部账号当天完成。

## 升级与故障处理

更新前确认当前批次已经停止或自然结束，保留本地 `.env`、`config.json`、会话库及运行数据备份。然后更新源码、安装锁定依赖、运行检查与构建，再重启本地服务。

若出现“身份无法确认”“旧调度锁拥有者不明”或“启动预留无法关联 PID”，先核对本轮记录及对应进程。不要直接删除数据库或锁来强行启动第二轮，也不要把状态清空当作恢复成功。

`.control-api/`、`monitor/data/`、`sessions/` 和 `logs/` 是本地运行数据，不应加入公开源码提交。通知与诊断可能包含账号页面内容，分享故障记录前先检查实际内容。
